# S11-SecSplit — Stage 5 amendments to design v1 (SHA-256 ddf7068a…68dd)

A1–A9: recorded before any held-out injection or cross-tool run (development seeds 0–4 only). Exception: A7 followed the audit-only CIC/UNSW scale checks (worked examples, S3/S5). **A10 is POST-RESULT** (see below). **A11 is the pre-registered validation protocol for A10 (NB3), written before NB3 was built or run.** **A12 is the pre-registered protocol for NB5, written before NB5 was built or run.** **A13 is the pre-registered read-only diagnostic (NB6), written before NB6 was built or run.**

- **A1 (D3 thresholds, pre-result).** Overlap thresholds for `5tuple`/`hostpair`/`session` lowered from 0.05 to 0.005 (WARN). Reason: with 0.05 the S2 criterion at ρ = 0.01 is unreachable by construction, and any group overlap in a group-disjoint protocol is worth reporting; users can raise it.
- **A2 (D4 capture level).** Units with < 10 groups (e.g. capture days) use leave-one-group-out folds; F and Δ are averaged over valid folds (as pilot A3/A8).
- **A3 (D5 verification, bug found on dev seed 0).** Relative tolerance on large values (timestamps ≈1.5e9) accepted pairs 15,000 s apart. Columns with a known common precision are now compared exactly after rounding; others with rtol 1e-6; hashing uses exact rounded values when precision is known, 5 significant digits otherwise. Decimal detection uses a tolerance of 4 ulp (was 1e-9·|x|, which made every large value look integer).
- **A4 (D5 alignment, dev seeds 0–4).** Distribution matching fails when copied rows are mixed with unrelated rows (the mixture's distribution differs). Added (i) an exact-value-overlap stage for high-cardinality, full-precision columns (rounded or integer columns excluded: chance overlap); (ii) a first matching pass on strongly aligned columns (name, value overlap) when ≥4 exist, after which remaining numeric columns are aligned by agreement on verified pairs (≥0.9) and matching is rerun.
- **A5 (D7, extra condition).** Added transform `renameall` (every column renamed, incl. metadata), reported separately; not part of criterion S2.
- **A6 (D8 scope, pre-result).** Cross-tool comparison on held-out seeds 100–109, ρ ∈ {0, 0.01, 0.05}, conditions {defaults, features, oracle} and lineage transforms {rename, round3, colsubset, combo, renameall}. Detection rules fixed before running.
- **A7 (engineering, from the CIC scale check; S5).** Memory fixes; CIC audit 4.91 GB peak, 180 s.
- **A8 (D8 secondary detection rule, before held-out runs).** "Split-leakage checks only" secondary rule for leakcheck/deepchecks; both rules reported.
- **A9 (D8, dataleaks runtime).** Defaults on a documented subset; main comparison uses `dataleaks_nonear`; 900-s limit per job.
- **A10 (D5 verification, 2026-10-27) — POST-RESULT; ADOPTED AS DEFAULT IN 0.1.1 (author decision 22:55), 0.1.0 behaviour kept behind an explicit flag.** Specified AFTER seeing the NB1 S4 negative-control results. Change: a verified pair additionally needs the agreeing values to carry ≥ log2(n_B) + 20 bits of self-information (per-column value frequencies in the streamed B chunk, +1 smoothing); refinement seeds must pass it too. Margin fixed before any amended result. NB2 results (verified against per-file JSONs): positive control unchanged (1.000; reverse 0.0068); all 8 negative directions 0 matches (frozen 4/8 failing); S2 lineage cells identical to frozen in all 36 cells; matched > planted 0. The paper keeps stating that 0.1.0 failed the pre-specified negative-control criterion and that A10 is post hoc.
